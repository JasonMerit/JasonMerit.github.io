Introduction (Jason)

For the final project, we opted to go with the project; “Object Selection,” since this offered a well-defined scope but still left room for self-exploration and interpretation of different variations of the initial project.
Object selection is a rather interesting problem, as it doesn’t necessarily appear very intuitive to solve. Perhaps ray casting can be used, but determining the mouse position when clicked and whether an irregular shape contains the mouse position is non-trivial.
To further develop this idea of object selection, we wanted to also incorporate some different elements from the course. This led us to decide to create a simple solar system simulator where a user clicks to select a planet.

Method (Amalie)

As previously stated, we included several methods introduced in the course, such as:

  • Creating spheres using recursive subdivision of triangles.
  • Applying 2-dimensional textures from loaded images to 3-dimensional objects.

We also made use of simple projection and transformations in order to both see the entirety of the solar system and properly emulate how the planets of a solar system behave. This includes how the planets rotate relative to themselves and each other, and how fast they orbit the sun depending on their orbital placement.
At the early stages of development, much of the methods used were taken from Worksheet 6 Part 3, as it related to rendering the earth with an image texture.
Specifically for the object selection part, we started from the methods supplied in the project description and developed them further. This included detecting when a cube is clicked by reading the pixel value as it appears on the canvas. To detect different objects, we had to extend the method, by coloring each planet its own color during the selection check.

Implementation (Jason)

To determine whether a cube is clicked, the following steps are performed:

  1. Upon mouse press, the cube is colored red.
  2. Read the pixel color at the point of the mouse.
  3. Redraw the cube in its original color.
  4. If the pixel color is red, the cube was selected.

Looking through the points, we’ve been taught all except reading the pixel value at a specific point. Since this is such a basic procedure, there should be a method for it. This is gl.readPixels, which returns a block of pixels on the requested area on the canvas.
We had to break the render method into draw and tick to allow for drawing without updating the rotation.
A few luxury features were added. Since a planet like Mercury is relatively small and has a relatively fast orbit around the sun, it is hard to select. To compensate, when drawing the spheres during the selection check, they are unscaled. Meaning, they all have the same size as the sun. Another feature is the view targeting the selected sphere planet. This is done by extracting the position of the selected sphere and passing it to the ‘lookAt’ parameter when defining the view matrix. It is also possible to zoom in and out by scrolling.

Results (Amalie)

Our results turned out as expected. The solar system appears as eight spheres, each with their own size, rotation, and translation. When you click on a planet or the sun, it was implemented such that the object in question would be re-drawn in a white color.
It worked as described in the method, showing a relatively realistic solar system with added modifications to enable user interactions, i.e., object selection.

Discussion (Amalie)

During the process of developing this project, certain modifications were made, due to new issues arising that we hadn’t previously thought of. An example of this, stemmed from our decision to draw a somewhat realistic solar system, meaning that the dimensions and sizes of the planets followed the actual ones to some degree. Because of this decision, we found that object selection was a particular challenge for selecting especially the small planets closer to the sun, because they were both very small and orbited the sun much faster than the remaining larger planets.
